# WatchKit — Quality Scorecard

Scored under The Elite Software Master Prompt v1.1, §17. Every score names its evidence; a score without evidence would be a Fail. This file is updated in the same change as the work it scores.

**State at v0.2.0: total 85.4/100 — the release bar (total ≥ 85, no dimension below 3, no Fail) is met for the local gate.** Two recorded waivers remain (Performance and Scalability measurements), and Windows runtime behaviour is Partially Verified: CI's real MSVC build is the link gate, and an on-machine field pass has not yet run. **The v0.2 `ReadDirectoryChangesW` runtime path is Unverified**: it compiles and clippy/checks clean for `x86_64-pc-windows-msvc` in the local gate, and its pure halves (buffer parser, snapshot merge) are unit-tested on Linux, but no Windows machine has run the native thread yet.

| Dimension | Score (0–5) | Verdict | Evidence |
|---|---|---|---|
| Correctness (weight 14) | 4 | Pass | Full WinDevKit gate green locally (fmt, clippy both targets with `-D warnings`, all 48 tests): detection, the whole coalescing table, queue-overflow accounting, cache invalidation, plus the v0.2 parser/merge/rescan convergence tests — each with a named deterministic test (see `docs/PARITY.md`). Not 5: behaviour on a real Windows machine is Unverified until a field pass — the native thread's runtime is exactly that gap; the VM gate is Linux evidence. |

## What moves the score

1. On-machine Windows field pass — now including the native backend (create with `"backend":"native"`, live file changes, an overflow burst, `wa_close` while events are pending; raises Correctness; anything found is fixed forward with a regression test).
2. A recorded large-tree scan benchmark (closes the Performance waiver and the Scalability follow-up in one exercise).
3. Coverage measurement, or recording test-count evidence as the accepted substitute (closes the Test evidence note).
